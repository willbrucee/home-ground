# Home Ground

A daily geography + sport guessing game. You get an athlete or a team; drop a pin on the city they're
from (an athlete's birthplace, or the city a team plays its home games in). Five rounds a day,
the same five for everyone.

## Running it

It's a static site: plain HTML, CSS and JavaScript with no build step. Browsers won't load the data files
from a page opened straight from disk, so serve the folder:

```sh
cd home-ground
python3 -m http.server 8000
# open http://localhost:8000
```

Any static host works for publishing: GitHub Pages, Netlify, Cloudflare Pages, itch.io.

Handy URL switches: add `?flat` for a flat map instead of the globe.

The claude.ai artifact preview can't load outside images, so there the game falls back to plain
country shapes instead of satellite imagery. GitHub Pages and other normal hosts show the imagery.

```

js/geo.js               distance and great-circle maths
js/units.js             km / miles display (everything is stored in km)
js/tiers.js             result tiers, colours and reaction lines
js/effects.js           the short celebration effects
data/players.json       the player/team list the game loads (generated, see below)
data/overrides.json     your additions and removals (merged in by the build)
data/review.csv         every entry sorted by fame, for checking by eye (generated)
data/countries.geojson  country shapes for "Reveal country" and the no-imagery fallback (generated)
scripts/                data scripts (Python 3, no extra packages)
vendor/                 MapLibre GL JS 5.6.0
```

## Player data

Every entry in `data/players.json` has this shape:

```json
{
  "id": "wd-Q615",
  "name": "Lionel Messi",
  "sport": "Football",
  "type": "athlete",
  "city": "Rosario",
  "country": "Argentina",
  "lat": -32.947,
  "lng": -60.639,
  "radius_km": 8,
  "difficulty": 1,
  "fame": 312.4,
  "achievement": "Ballon d'Or · FIFA World Player of the Year",
  "hint": "optional, teams only: \"Home ground: Old Trafford\" (shown on the result card)",
  "image": "https://commons.wikimedia.org/wiki/Special:FilePath/Lionel_Messi_2018.jpg?width=400",
  "imageAuthor": "Jane Doe",
  "imageLicense": "CC BY-SA 3.0",
  "imagePage": "https://commons.wikimedia.org/wiki/File:Lionel_Messi_2018.jpg"
}
```

- `type` is `"athlete"` (placed at their birthplace) or `"team"` (placed at their home stadium's town).
- `radius_km` is how big the city is: any guess within this distance of the centre counts as "inside the
  city" (0 km off, a hole in one). It's the radius of a circle with the city's area on Wikidata, or an
  estimate from its population, kept between 8 and 60 km.
- `difficulty` is 1 (household name), 2 (well known) or 3 (fans will know). Each day uses three 1s and
  two 2s (change `ROUND_DIFFICULTY` in `js/config.js`).
- `fame` is sitelinks plus an achievement bonus (see below). `achievement` is built from Wikidata's
  awards and "winner of" records; it's shown as "Honours" after each guess.
- The four `image…` fields are optional and come as a set (see Pictures below).
- `id` must be unique and must never change once the game is live. The daily order is built from ids.
- `country` must match a shape in `data/countries.geojson` (directly or via the aliases in
  `scripts/validate_players.py`), or "Reveal country" has nothing to highlight.
  `python3 scripts/build_countries.py` lists any entry that doesn't match.

### Adding or removing players: data/overrides.json

`players.json` is regenerated by the build, so don't edit it by hand. Use `data/overrides.json`:

```json
{
  "exclude": { "Q154373": "why it's out (for you)" },
  "include": [ { "id": "Q615", "type": "athlete", "sport": "Football", "note": "Lionel Messi" } ],
  "no_image": [ "Q81888" ]
}
```

- **exclude**: Wikidata ids to leave out, whatever their fame.
- **include**: ids to add even if they wouldn't make the cut. Find the id on wikidata.org (the "Q" number
  in the page address). The build fetches their birthplace or stadium, achievements and picture.
- **no_image**: ids that should show the initials badge instead of their picture.

Then run the build (below) and commit the new `players.json`.

### Rebuilding from Wikidata

Run these in order:

```sh
python3 scripts/build_players.py    # who's in: data/players.json and data/review.csv (resets data/reserve.json)
python3 scripts/pick_images.py      # a picture for each; entries without a good one go to data/reserve.json
python3 scripts/build_vault.py      # the Vault's facts: data/vault.json
```

Add `--fresh` to any of them to ignore the cache. `scripts/build_places.py` (the town list for the Full time
screen, from GeoNames cities15000) only needs running if you want a newer copy.

Wikidata's query service is often busy. The scripts retry, and cache every answer (in small batches) in
`scripts/.cache/`, so if one stops, just run it again: it carries on where it left off. Wikipedia's own
APIs rate-limit us quickly, so pageviews and article intros are asked for through the Wikidata query
service (its MWAPI bridge).

**Who gets in.** Candidates are each sport's best-known people and its top leagues' teams. To stay in,
an entry must clear **both** fame bars:

- **Sitelinks**: Wikipedia language editions with an article on them (Messi 227). Athletes 25+, teams 15+,
  lower for sports big in only a few countries (`SITELINK_BAR`).
- **Pageviews**: English Wikipedia views over the **last 60 days** (Wikipedia only reports 60 days through
  this route). Athletes 30,000+, teams 40,000+, lower for sports mostly followed outside the English-speaking
  world (`VIEWS_BAR`).

Then athletes need a **major win** in their sport (a headline title or individual award, an Olympic medal,
a hall of fame, 5+ honours, or, because Wikidata's trophy records are patchy, a star of the sport by
description with a huge readership). People born before 1965 must also be legends (50+ sitelinks or
40,000+ views).

- **Fame score** combines both signals (their geometric mean, so you need both), plus a small bonus for honours.
- **Balance**: each sport and league keeps only its top N by fame.
- **Difficulty**: over the whole pool, the top 35% by fame are 1, the next 40% are 2, the rest 3. Each day
  has two 1s, two 2s and a 3, in that order (`ROUND_DIFFICULTY` in `js/config.js`).

The minimums and quotas are in the lists at the top of `scripts/build_players.py`. Each line also has
the Wikidata id and its expected label, which is checked at the start of every run, so a wrong id gets
skipped instead of pulling in junk.

**Review list.** Every build writes `data/review.csv`, sorted by fame, with sitelinks, achievement count,
difficulty, city radius and whether there's a picture. Open it in a spreadsheet and look for odd ones.
The build also prints athletes who held public office or were convicted of a crime, since they're often
famous for something else. Add any that don't belong to `exclude`.

### Validation

`python3 scripts/validate_players.py` checks every entry:

- **Errors** (dropped by the build): missing fields, bad `type`/`difficulty`, coordinates at 0,0 or out of range.
- **Warnings** (kept, worth a look): the point lands in a different country from the one named (coastal
  towns get 30 km of slack), the country name isn't recognised, or the same name appears twice.

Wikidata sometimes has odd birthplaces (a hospital, a district, an old country). The warnings are the place
to catch them. The fix is usually on Wikidata itself; or leave the entry out with `exclude`.

### How the daily pick works

Each difficulty group is put in a fixed shuffled order, sorted by a hash of each entry's `id`. Day 1 takes
the first slots, day 2 the next, and so on, so nothing repeats until the whole group has been used. Then a
new order starts. Everyone computes the same order, so everyone gets the same five. Adding players slots
them into the order without reshuffling the others, though days that haven't happened yet can shift.

### Pictures and anti-cheat

Pictures are left out automatically when the file name mentions the answer city (e.g. "Old Trafford
Manchester.jpg"). The script can't read text inside a picture, though, so it prints a list of team
logos whose team name doesn't already include the city. Glance through those for crests that
spell out the city ("Ajax Amsterdam" style) and add any that do to `no_image` in `data/overrides.json`.

Without a picture, the game shows an initials badge with a small icon for the sport, never a broken image.

### Licences

- Photos on Wikimedia Commons are free to reuse, but most licences (CC BY, CC BY-SA) require credit.
  The game shows the author and licence behind the (i) on each picture and on the scorecard.
- Team logos are trademarks even when Commons hosts them as public domain (simple text logos) or under
  a free licence. Showing them in a small, free, non-commercial game is low-risk, but check with the
  clubs' and leagues' rules (or drop logos) before any commercial or large public launch.
- Images are loaded straight from Wikimedia ("hotlinking"), which Wikimedia allows. For a big audience,
  download and serve them yourself to be polite to their servers.
